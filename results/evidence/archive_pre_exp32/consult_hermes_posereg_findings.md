# 对抗审查:long-horizon 位姿正则离线探针发现

> 审查者:Hermes Agent(对抗审查角色)。2026-08-11。
> 审查对象:`results/probes/pose_reg/pose_reg_findings.md`(exp-v3-15)。
> 方法:直接重算 9 个 `*_trj.json`(edge3/p2t/dba × seed0/1/2,各 580 帧 4×4 SE(3))的每一个断言。
> 结论先行:**发现文档的核心数字与解读均有不可复现或方向性错误,据此作出的三候选裁决不成立。**

---

## (1) 分解逻辑漏洞

### A. "方向≈100%、长度≈0%"分解 —— **不可复现,数据直接反驳**

发现文档断言:`GTlen+estdir`(纯方向误差)ATE≈170cm≈全ATE;`estlen+GTdir`(纯长度误差)≈0cm。

我用同一批 json 重算(edge3 seed0,与文档同源):

| 分解 | evo SE(3) Umeyama 对齐后 | 帧内 frame0 gauge 原始 RMSE |
|---|---|---|
| 全 ATE(est vs gt) | **9.16 cm**(= tracking_raw,✓ 复现) | 158.5 cm |
| GTlen+estdir(纯方向) | **11.73 cm** | 269.8 cm |
| estlen+GTdir(纯长度) | **12.00 cm** | 229.5 cm |

对齐口径下方向 11.7 / 长度 12.0 —— **两个通道贡献几乎相等**,不是 100% vs 0%。
原始口径下方向 269 / 长度 229 —— 方向略大但长度绝非 0。

文档的 "170 / 0" 数字在 json 上**无法用任何口径复现**:既不是 evo 对齐 ATE(9.16),也不是原始 RMSE(158),更不是各臂均值。文档未交代这个 170/0 用的什么度量,极可能是脚本 bug 或未记录的预处理。"长度≈0%" 是整个裁决链的支点,而这个支点是假的。

### B. "rot_ratio 0.35-0.39,欠转" —— **方向读反,真实错误是转向相反**

文档断言:累计旋转 est 177-200° vs GT 511°,ratio 0.35-0.39,est "转弯转得不够"(欠转)。

我逐帧提取 yaw(atan2(R[1,0],R[0,0])):

```
f0:   est_yaw=  0.7   gt_yaw=  0.7
f100: est_yaw= 11.8   gt_yaw=-47.5
f200: est_yaw=109.4   gt_yaw=-103.7
f250: est_yaw=169.0   gt_yaw=-146.1   ← est 到 +169°,GT 到 -146°
f400: est_yaw= 55.7   gt_yaw= -89.2
f579: est_yaw= -8.5   gt_yaw=   0.2
```

**est 顺时针转(+173°),GT 逆时针转(-161°)。9/9 run 全同。这是转向相反,不是欠转。**

"0.35 ratio" 是用测地线增量绝对值求和得到的假象:测地线角永远为正,把 "est 往右转 170°" 和 "GT 往左转 160°" 都记成正数,再比大小,自然得到一个 <1 的比值。这个比值没有任何物理意义——它把一个**符号错误**伪装成了**幅值不足**。

yaw 总行程(unwrap 后):est 371° vs GT 380°,ratio=0.976。**est 转的总量和 GT 几乎一样多,只是转反了。**

### C. 其他不可复现的数字

| 文档断言 | json 实算 | 偏差 |
|---|---|---|
| pathLen 比 1.10-1.12 | 1.27-1.34 | 过走被低估 ~2.5× |
| raw cam dist 299cm | mean 132cm / max 244cm | 高估 2.3× |
| 死推 208→174cm | 不可复现(最近的是原始 RMSE 158) | 数字来源不明 |
| rot_ratio 0.35-0.39 | 测地线 0.24-0.30;yaw 行程 0.976 | 见上 |

"死推 208→174" 的 208 和 174 在 json 上找不到对应物。文档可能用了未记录的预处理或脚本 bug。**基于这些数字的 "步长正则救不了" 结论,数字层面站不住,需用可复现口径重算后才能判。**

### D. 分解的方法论漏洞(即使数字修正后)

退一步,假设重算后方向贡献确实 > 长度贡献。把 ATE 拆成 "纯方向" 和 "纯长度" 两个反事实轨迹,有一个隐藏假设:误差通道可加性。但 est 的方向误差和长度误差是**同一个跟踪器同帧耦合产出**的,不存在 "只动方向不动长度" 的真实扰动。这种分解只能定性说 "哪个通道误差更大",不能推出 "正则 A 通道无效"——因为正则 A 会改变跟踪器的优化 landscape,间接影响 B 通道。文档从 "长度贡献小" 跳到 "步长正则无用" 是过度推断。

## (2) 对候选①②③的裁定

### 候选① 轨迹平滑先验 —— 文档判 "放大欠转,无用"。**裁定:推翻,需重审。**

文档的判据是 "平滑会碾平欠转 → 更不转 → 更偏"。但真实错误是**转向相反**,不是欠转。平滑(惩罚角加速度)对一个符号错误的旋转会起**阻尼**作用——它压低角速度幅值,可能减小偏离,也可能不改变符号,但 "放大欠转" 的因果链建立在假的 "欠转" 前提上,不成立。

更关键:est yaw 在 f100-f250 区间从 +12° 单调冲到 +169°(角速度 ~1°/帧),GT 同期从 -48° 到 -146°。这是一个**高速反向漂移段**。平滑先验在这个段上会直接抑制 est 的角速度飙升,方向上是有利的。文档没有做这个段级分析就全局判死。

**裁定:候选①不能基于当前探针判死。需要用 "转向相反" 的正确诊断重做平滑先验的预期分析。**

### 候选② 航位推算死区一致 —— 文档判 "约束平移=贡献≈0 通道,无用"。

这个裁定的前提 "长度贡献≈0" 已被证伪(实算长度贡献 ≈ 方向贡献)。此外,航位推算由同一跟踪增量构造、继承同一偏置的批评是有效的——但这批评对候选①(平滑也用 est 自己的增量)同样成立,文档没有一视同仁。

**裁定:候选②的 "贡献≈0 通道" 前提假,但 "继承同一偏置、无新信息" 的批评有效。结论(不值得做)可能碰巧对,但理由要换成 "不提供独立观测" 而非 "约束 0 贡献通道"。**

### 候选③ 特征锚 —— 文档判 "K=60 完美GT锚反而更差(9.16→42.9),已否掉"。**裁定:推翻,实验构造有缺陷,不能否掉特征锚。**

我复现了 K=60 → 36cm(同数量级,趋势同)。但文档的锚实验做的是:**每 K 帧把姿态硬拉到 GT,段内用 est 自己的相对增量传播**。这测的是 "重播 est 的坏增量 + 周期性重置 gauge",不是特征锚。

特征锚的真实机制是 **re-observe features → re-solve pose → 产生新的、独立的位姿增量**。文档的实验把 "增量" 固定为 est 的原增量,只换了 gauge 起点,当然不改善——它把特征锚退化成了 "GT 重定位 + est 增量回放"。

我做了一个对照:**GT 锚之间用插值(模拟 re-solve 产生合理增量)**:

| K | 文档方法(est 增量回放) | GT 锚间插值(模拟 re-solve) |
|---|---|---|
| 15 | 12.9 cm | **1.08 cm** |
| 30 | 24.6 cm | **2.76 cm** |
| 60 | 42.9 cm | **7.67 cm** |

GT 锚间插值 K=60 → 7.67cm,**优于 baseline 9.16cm**。这说明:如果有独立观测能在锚点之间产生合理增量(而不是回放 est 的反向漂移),特征锚是**有正向价值**的。

**裁定:候选③未被否掉。文档的锚实验是 strawman(稻草人)。特征锚方向仍 open,且正向证据(插值 K=60 改善)已存在。**

## (3) 最锋利的可执行判别实验

### "yaw 符号翻转探针":est 是否系统性转向相反?能否用现成信号纠正?

**动机**:正确诊断是 est yaw 与 GT yaw **符号相反**(est +173° / GT -161°),不是欠转。这是整个探针最硬、最可复现的发现(9/9 全同)。如果能确认这是一个**可预测的符号偏置**而非随机噪声,就存在一个极低成本的纠正信号。

**实验构造(零 GPU,读现有 json)**:

1. **符号一致性检验**:对 9 个 run,逐帧计算 `sign(est_yaw_rate) vs sign(gt_yaw_rate)`。如果在 |yaw_rate|>阈值(如 0.3°/帧)的帧上,符号一致率显著 <50%(预期 ~0%),则确认 "转向相反" 是系统性偏置,不是噪声。
2. **分段定位翻转点**:用 change-point detection 找 est yaw 从 "跟随 GT 方向" 切到 "反向" 的帧。文档的 f0-f50 区间 est_yaw 0.7→1.9 / GT 0.7→-12.5,符号已经在 f50 附近分裂。定位精确翻转帧 → 看是否对应跟踪 loss / mask 边界 / 关键帧切换。
3. **可纠正性上界**:构造一个 "yaw 符号翻转 oracle"——对 est yaw 做 `yaw_corrected = -yaw_est`(只翻符号,不动幅值),重算 ATE。如果 ATE 大幅下降(预期从 9.16 降到个位数),证明 "转向相反" 是 ATE 的主导可纠正成分,且**一个符号先验就能抓到**——这直接 open 旋转通道正则方向,且无需绝对航向参考(只需检测转向方向)。

**为什么这个实验最锋利**:
- 它直接测试 "转向相反" 而非 "欠转",而前者才是数据支持的真实现象。
- 步骤 1-2 零 GPU,30 分钟出结果。
- 步骤 3 的 "符号翻转 oracle" 是一个 **upper-bound 探针**:如果翻转符号后 ATE 仍高,说明符号不是主导,旋转正则方向确实死;如果 ATE 崩到个位数,说明符号是主导可纠正成分,存在一个**免绝对航向**的旋转正则空间(检测转向方向 + 符号先验),这恰恰是文档声称 "无绝对航向参考就无济于事" 所否定的方向。
- 它用现成信号(yaw rate 符号),不需要新观测源,不依赖特征/IMU/闭环。

**预期结果与判据**:
- 若符号翻转 oracle ATE < 3cm → 旋转正则方向 **GO**,且 "需绝对航向" 断言被证伪。
- 若 3-9cm → 部分可纠正,值得做角速度方向先验的 spike。
- 若 >9cm(不变或更差)→ 符号不是主导,旋转正则方向确实死,文档结论(换口径后)成立。

**落盘**:结果写入 `results/probes/pose_reg/yaw_sign_flip_probe.md`,含 9 run 符号一致率表 + 翻转帧定位 + 符号翻转 oracle ATE。
