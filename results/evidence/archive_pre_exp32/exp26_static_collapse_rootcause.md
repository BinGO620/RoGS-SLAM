# （原文）f3_st_hf 静态崩溃 — 根因定位到 s→w 聚合算子

> exp26（2026-08-17），零 GPU，全部从已有 run 的盘上数据得出。
> **本文推翻 exp25 的机制叙事**（"位姿误差污染 e_flow → 跨帧正反馈"），
> 并把 FULLKERN regime 分裂（静态 6/6 全变差）归因到一个构造性缺陷。

## 1. 现象：不是渐进漂移，是 frame 371 的离散失败

四个臂的 ATE 演化（`plot/stats_*.json`，一直在每个 run 里，从未被读过）：

| frame | control s0 | oracle s0 | oracle s1 | fix s0 |
|---|---|---|---|---|
| 346 | 1.62 | 1.58 | 1.62 | 1.70 |
| **371** | **3.32** | 1.87 | **3.38** | 2.01 |
| 396 | 10.71 | 2.01 | 10.82 | 2.10 |
| 421 | 19.07 | 1.98 | 19.54 | 2.13 |
| 1071 | 35.40 | 2.64 | 37.44 | 2.89 |

**前 350 帧四个臂完全一致（~1.6cm）**，frame 371 一步翻倍，50 帧内到 19cm，
之后停在 35-38 不再增长（跟踪其实恢复，绝对偏移永久烙进去）。
所有崩掉的 run **都在同一帧 371**（control s0 / oracle s1 / oracle s2）。

## 2. frame 371 是序列属性，不是我们造成的

- GT 帧间平移从 f348 的 0.16cm 升到 f396 的 1.89cm（全序列 p95 = 1.394cm）⇒ **进前 5%**
- 旋转不是元凶：371 附近 0.78-1.08°（中位 0.83），全序列最快的在 f839-941（3.5-4.8°）反而无事
- `flow_valid_frac` 在 f368-380 从 0.54 掉到 0.43（−20%）
- **该量在四个 run 里逐帧完全相同** ⇒ 只依赖观测深度与相对位姿，是序列的难点，不是方法的产物

## 3. e_flow 不是判别量（推翻 exp25 叙事）

oracle 臂用 GT 相对位姿喂 `rigid_flow` ⇒ 其 `e_flow` 与本 run 自身轨迹无关。实测：

**三个 oracle run 的 `e_flow_mean_valid` 逐帧完全相同，1077 帧全同、0 帧不同。**

而这三个 run 的结局是 **2.85 活 / 37.34 崩 / 34.66 崩**。

⇒ 同样的 e_flow 可活可崩，**e_flow 不决定生死**。
exp25 的"位姿误差污染 e_flow → 跨帧正反馈 → 崩"不解释这条序列的失败，
建立其上的修法 B 也就没有可靠工作的理由。

**精确表述（勿矫枉过正）**：改 e_flow 确实提高逃逸率
（control 0/4 活 → oracle+fix 3/6 活），所以 e_flow 非无关；
但它**不是判别量**。exp25 那条干净的"12.4× 因果链"不成立。

（离线探针测到的"e_flow 对位姿扰动敏感"仍是真测量，只是不是这里的操作性原因。）

## 4. 根因：`cauchy_tracking_weight` 对 s 的绝对水平完全不敏感

```
d = 1 - s ;  tau = median(d) + 1.4826*MAD(d) + eps ;  w = 1/(1 + (d/tau)^2)
```

`tau` 由 d **自己的**中位数与 MAD 决定 ⇒ 把 d 整体乘以任意常数 c，
med→c·med、mad→c·mad、tau→c·tau，**d/tau 不变 ⇒ w 不变**。
即 **w 只看 d 分布的形状，永远看不见它的量级**。

数值验证（`cauchy_tracking_weight`，同一分布形状整体缩放）：

| 场景 | mean_s | min_s | **mean_w** | **w<0.5 的像素比例** |
|---|---|---|---|---|
| 纯静态 s∈[0.97,1.00] | 0.9850 | 0.9700 | **0.7438** | **0.1303** |
| 静态 s∈[0.90,1.00] | 0.9500 | 0.9000 | **0.7438** | **0.1303** |
| 中等 s∈[0.60,1.00] | 0.8001 | 0.6000 | **0.7438** | **0.1303** |
| 动态 s∈[0.10,1.00] | 0.5502 | 0.1000 | **0.7438** | **0.1303** |

**小数点后四位完全相同。**

真实数据完全对上——8 条序列（4 静 4 动）的全 run 均值：

| 序列 | ATE | mean_w | mean_s | e_flow | flow_valid |
|---|---|---|---|---|---|
| f3_st_hf 静态(崩) | 36.09 | 0.626 | 0.718 | 0.146 | 0.669 |
| f3_st_xyz 静态 | 2.32 | 0.571 | 0.758 | 0.095 | 0.626 |
| f3_office 静态 | 1.58 | 0.664 | 0.682 | 0.111 | 0.833 |
| f1_desk 静态 | 1.44 | 0.635 | 0.684 | 0.186 | 0.738 |
| crowd 动态 | 3.38 | 0.619 | 0.668 | 0.192 | 0.841 |
| crowd2 动态 | 34.84 | 0.635 | 0.630 | 0.236 | 0.838 |

`mean_w` 全在 **0.57-0.66**，静态动态无差别 ⇒
**方法在纯静态桌面序列上照样丢掉 ~38% 的光度信号。**

docstring 写的 `s -> 1 => w -> 1 (no-harm)` 只在 d **完全无展度**时成立。
真实数据永远有展度（传感器噪声 / 几何残差 / opacity），
所以每一帧都按同样比例削掉尾巴——**不管那条尾巴是真动态还是纯噪声**。

## 5. 一条缺陷解释全部已知现象

| 现象 | 解释 |
|---|---|
| 动态序列 4-14× 增益 | 尾巴确实是 mover，削对了 ✅ |
| 静态 6/6 全变差（FULLKERN regime 分裂） | 尾巴是噪声，削掉纯亏 ❌ |
| f3_st_hf 在 371 崩而 vanilla（2.80cm）不崩 | 那里本来就难（flow 支持只剩 43%），再少 38% 信号撑不住 |
| e_flow 相同却可活可崩 | 无论 e_flow 取值如何，w 的分布都一样 |

⚠ **已证 vs 推断**：已证 =（a）w 对尺度严格不变（数值）、（b）mean_w 在 8 序列上恒定
（实测）、（c）vanilla 2.80 vs ours 35.59（主表）、（d）371 处 flow 支持掉 20%（实测）。
**推断** = "丢 38% 信号导致 371 处失败"这条因果链。
直接判据 = f3_st_hf 上跑一个 `w≡1`（ReliabilitySignal 下权重关闭）的臂，
若不再在 371 崩 ⇒ 因果坐实。**1 run 即可，不需要 seed 扫。**

## 6. 这条 memory 里早就记过一次

memory `reliability-signal-selectivity`：
> "NOT coverage — it's the **s→w aggregation**. Frame-adaptive Cauchy
> tau=median(d)+MAD is **majority-dominated** ... Lever = **fixed/percentile tau**
> + raise geo_scale_floor, NOT more flow"

判断是对的，杠杆也点明了。但当时把修法瞄准了 **MAP admission**，
**tracking down-weight 从来没改过**；之后几个会话（deferred / eviction /
terminal compression / P7 cue-split / 修法 B）全部绕开了它。

## 7. 修法方向

把 tau 从**帧自适应**改成**绝对的**（固定 tau / s 的绝对阈值 / 全局分位），
使静态帧的 mean_w 真正趋近 1、动态帧保持选择性。

判据：静态序列 mean_w 推到 ~0.95 且 ATE 不劣于 vanilla，动态序列 mean_w 保持 ~0.6 且
增益不掉。**这是 no-harm 性质能不能成立的分水岭。**
