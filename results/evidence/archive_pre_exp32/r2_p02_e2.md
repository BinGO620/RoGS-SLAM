# R2-P02-E2 — balloon make-or-break: **VOID (mechanism never fired)**

Date: 2026-07-28 · Hardware: RTX 2060 (GPU0) · Sequence: Bonn `balloon` (439 frames),
self-tracked, `--eval` · Arms A/B/C/D/E × seed{0,1} (C seed0-only per pre-reg §7) ·
9/9 runs exit=0 · Raw: `results/evidence/r2_p02_e2_results.jsonl`,
`results/runs/R2-P02/R2-P02-E2/` (consolelogs + `mapping_raw.csv` + PLYs).

## 0. Headline

**The α exit pass never fired once, in any run.** Every keyframe in every D/E run
logged `reset 0, carved 0`; fill (gated behind a non-zero exit delta) logged
nothing at all. Arms **B, C, D and E therefore executed the same map-mutating
algorithm** — the α ledger was written but never read by any actuator.

Consequence: **CHECKPOINT-1 and CHECKPOINT-2 are VOID, not pass/fail.** The
pre-registered contrasts were not tested. Every inter-arm difference reported
below is run-to-run nondeterminism.

## 2. Proof the mechanism was inert

**(a) Actuator logs.** `alpha-exit` lines: D0 25, D1 25, E0 26, E1 25 — *all*
`reset 0, carved 0`. `alpha-fill` lines: **0** in both E runs. `alpha-lifecycle
step skipped` (the try/except fallback): **0** — the code ran cleanly and simply
selected nothing.

**(b) The α ledger itself,** read out of each run's `final_after_opt` PLY
(`save_ply` persists `static_prob`/`static_obs_count`; `clone_obj` deep-copies
them across the process boundary, and `StaticProb`/`TriReliability`/`Reliability`
are all disabled, so the lifecycle is the ledger's only writer — the PLY *is* the
backend's ledger). Script: `results/runs/R2-P02/R2-P02-E2/_alpha_forensics.py`.

| arm | α min | α median | α max | #(α<0.35) | #(α<0.20) | obs_count max |
|---|---|---|---|---|---|---|
| A / B (all seeds) | 0.7000 | 0.7000 | 0.7000 | 0 | 0 | 0 |
| C observe s0 | 0.6300 | 0.7000 | 0.7300 | **0** | **0** | **2** |
| D exit s0 / s1 | 0.6300 | 0.7000 | 0.7300 | **0** | **0** | **1** |
| E exit+fill s0 / s1 | 0.6300 | 0.7000 | 0.7570 | **0** | **0** | **2** |

A/B are flat at the 0.7 init — correct, the block is absent so the step is
skipped (arm-B parity holds). For C/D/E the ledger's **entire lifetime range is
[0.63, 0.757]**, and those are exactly the one- and two-step EMA values from the
init: `0.9·0.7 + 0.1·0 = 0.63`, `0.9·0.7 + 0.1·1 = 0.73`, `0.9·0.73 + 0.1·1 =
0.757`. `obs_count` never exceeded **2** across 439 frames.

**(c) The gate arithmetic — the mechanism was unreachable by construction.**
With `ema_beta=0.9` and `initial_static_prob=0.7` (both defaults; the arm
overlays set only `mode`), crossing `tau_reset=0.35` needs `0.7·0.9ⁿ < 0.35`
→ **n ≥ 7 consecutive full-evidence updates**; crossing `tau_carve=0.20` needs
**n ≥ 12** *plus* `obs_count ≥ 3`. Observed effective ledger depth: **≤ 2**.
The exit gate could not have opened even with perfect dynamic evidence.

## 3. Three independent causes

1. **The ledger does not accumulate.** `obs_count ≤ 2` after 439 frames with ~26
   lifecycle events means per-Gaussian evidence is being reset. Prime suspect:
   `GaussianModel._extend_static_memory_state` falls back to
   `ensure_static_memory_state()` — a **full wipe of every α and every counter
   back to 0.7 / 0** — whenever `static_prob.shape[0] != prev_count`. It was
   silent. A reset counter + per-KF ledger diagnostics are now wired
   (`gaussian_model.py`, `slam_backend.py` `alpha-ledger` log line); a 120-frame
   instrumented smoke confirms or clears this.
2. **The EMA is far too slow for the event budget.** balloon commits only ~26
   keyframes, and the step runs once per keyframe → ≤26 updates *total* per
   Gaussian in the best case, against a β=0.9 time constant of 10 and a 7-update
   threshold crossing. Even a perfectly-persisted ledger barely arms before the
   sequence ends.
3. **Evidence is sampled at its systematic minimum.** `_alpha_lifecycle_step`
   runs immediately after `map(window, iters)` + `map(window, prune=True)` — i.e.
   right after the optimizer minimized depth L1 against this exact keyframe.
   The residual it reads is the *fitted* residual, so dynamic evidence is
   measured at the one point in the pipeline where it is smallest. Note the α
   histogram is skewed *upward* (2304 Gaussians rose into [0.70,0.80) vs 4941
   that fell into [0.60,0.69) on D s0), consistent with evidence ≈ 0 pulling α
   toward 1.

## 4. What the numbers actually measure: the null band

Because B/C/D/E share one map-mutating algorithm, E2 unintentionally ran a
**null-replicate experiment** — the first direct estimate of this metric's
run-to-run noise on balloon:

- seed0 replicates {B, C, D, E}: 22.252 / 23.046 / 21.992 / 22.882 → spread **1.05 cm**
- seed1 replicates {B, D, E}: 26.684 / 23.391 / 23.730 → spread **3.29 cm**
- arm A across campaigns (lifecycle-free, config unchanged): 23.547 in R2-P01-E2
  vs 21.563 / 22.074 here → shift **≈1.5–2.0 cm**
- Gaussian count is equally unstable: same algorithm, seed1 → 23274 / 28549 / **38022**

Every reported "effect" sits inside that band and is a difference between
replicates of one algorithm:

| claim | margin | verdict |
|---|---|---|
| CP-1 "D beats B" | 0.26 (s0) / 3.29 (s1) | VOID — same algorithm; s1 margin is B1's divergent run |
| CP-2 "E fails vs A" | 1.32 / 1.66 | VOID as an α test — this is the deferred-vs-prune contrast |
| "fill hurts, E worse than D" | 0.89 / 0.34 | VOID — fill never executed; same algorithm both sides |
| "B s1 blew up to 38022, D pulled it back" | — | VOID — B1 is a divergent run, not an exit effect |

**The one durable result:** pooling by real algorithm, prune (A: 21.563, 22.074;
mean 21.82) still beats the whole deferred family (7 runs, mean 23.43) on
vacated-region ghost — replicating R2-P01-E2. The deferred-entry ghost deficit
that motivated the α pivot is intact and still un-attacked.

**Metric-sensitivity caveat.** `vac_depth − static_depth` is only +0.08…+1.31 cm
on a 21–27 cm base, i.e. the "ghost" headline is ~95% global static-background
error. As instrumented it tracks overall map/pose quality far more than it tracks
the vacated region. Reporting the *contrast* (vacated minus non-vacated static)
would make the headline actually sensitive to the claim.

## 5. Process failures to fix (these let an inert arm reach make-or-break)

- **The E1 smoke already showed `reset 0, carved 0`** on every keyframe
  (`results/runs/R2-P02-E1-resmoke-optA/.../console.log`). E1 only asserted "does
  not crash", so an inert mechanism passed the gate.
- **The E2 canary band was 15 < vac_depth < 32 cm** — far too loose. It admitted
  arm A at 21.56 when the reference was 23.55 (a ~2 cm miss) and reported PASS.
- **No arm-activity metric exists.** `mapping_raw.csv` / `efficiency_raw.csv`
  carry no `alpha_exit_reset_total` / `alpha_carve_total` / `alpha_fill_inserted`
  column, so "the treatment did nothing" is invisible in the results table.

## 6. Root cause — FOUND AND FIXED (2026-07-28, post-mortem smokes)

Two 150-frame instrumented balloon smokes (`--fast`, arm D, 2060) settled it.

**The ledger wipe was innocent.** With the reset/grow counters wired
(`static_memory_reset_count` / `static_memory_extend_count`, commit `00d3ea5`),
the smoke reported `resets=0 grows=0` on every keyframe — the ledger was
perfectly in sync all along. The three silent "rebuild at default" paths
(`_extend_static_memory_state`, `prune_points`, `_prune_raw`) are now
preserve-and-count instead of wipe, but that is latent-footgun removal, not the
cause.

**The actual cause was the input.** `_alpha_lifecycle_step` was handed the
backend keyframe message's `depth_map`, which under prune/deferred is
`decision.immediate_depth_map` (`slam_frontend.py:1921`) — the **insertion**
depth map, i.e. only the pixels the current map does *not* already explain
(`_deduplicate_promotion` explicitly zeroes every explained pixel), and for
deferred nearly empty by construction. Since `depth_inconsistency_evidence`
requires `observed > 0.01`, the exit pass was **blind exactly where the map has
content — which is where ghosts live**. Evidence validity decayed as the map
filled in, starving the alpha ledger *and* the geometry test off one input.

Measured decay before the fix: `ev_valid_frac` 0.067 (KF25) → 0.0117 (KF108) →
**0.0002** (KF146), with `updated == ev_valid_at` exactly (183=183, 30=30, 1=1)
— i.e. evidence validity was the sole binding conjunct, while `proj_valid` (92%)
and `visible` (97%) were healthy all along.

Fix (commit `bd884b8`): pass `viewpoint.depth` (raw sensor depth), falling back
to `depth_map` only if the camera was cleaned.

| quantity (per KF) | before fix | after fix |
|---|---|---|
| `ev_valid_frac` | 0.067 → 0.0002 (decaying) | **0.85** (stable) |
| `updated` | 183 → 1 | **10010 – 15841** |
| `obs_max` | 1 | **11** |
| `obs_ge_min` (carve persistence gate) | 0 | **13795** |
| `a_min` | 0.6300 (one EMA step) | **0.2592** (past `tau_reset`=0.35) |
| `a_lt_reset` | 0 | **166 – 251** |
| `geom_front` | 1 – 28 | **1554 – 5787** |
| `alpha-exit` | `reset 0, carved 0` every KF | **`reset 250 / 179 / 97 / 126 / 96`** |

The first six keyframes still log `reset 0` and then the mechanism switches on —
that is alpha maturation, the designed behaviour. Zero lifecycle skips;
partial-trajectory ATE 0.177 → 0.182 m (unchanged within noise) while ~750
Gaussians now get opacity-reset, so the exit pass is not buying its effect with
tracking harm. 83 CPU/CUDA tests green.

**Still open:** `carved` remains 0 at 150 frames — mechanism B additionally needs
`alpha < tau_carve = 0.20` and `a_min` is 0.2592 and still descending, so it may
arm naturally over the full 439-frame sequence. That is a question for the
re-run, not a defect.

**Not yet done before an E2 re-run:** the arm-activity columns
(`alpha_exit_reset_total` / `carve_total` / `fill_inserted`) and the canary rule
that FAILS a treatment arm reporting zero activity (§5). Without those, a
re-run can silently repeat this failure.

## 7. Decision

CHECKPOINT-1 and CHECKPOINT-2 are recorded **VOID**. This is not a negative
result for the α exit/fill hypothesis — the hypothesis was not tested. The
pre-registration stands unchanged; the run is repeated once the mechanism
demonstrably acts. GO/KILL remains the user's call and is not invoked here.

## 8. Instrument calibration (2026-07-28) — the headline could not have resolved its own claim

E2's accident left something valuable: **seven runs of one identical
map-mutating algorithm** (B/C/D/E). That is a direct, measured noise floor.
Arm A is excluded from every null estimate below — it is a genuinely different
algorithm, and folding it in would hide a real effect inside the noise.

Method: `scripts/eval_vacated_posthoc.py` re-scores each finished run from its
saved PLY + poses (no SLAM time). All 18 post-hoc renders reproduce their run's
stored band metrics to **≤0.0007 dB**, so these are the in-run eval's own
numbers. Analysis: `scripts/analyze_ghost_metric_noise.py`.

### 8.2 The pre-registered headline is unusable, and the window does not save it

The vacated-minus-own-background depth gap over all 9 runs ranges **−2.17 to
+3.30 cm with no consistent sign**, against a 1.56 cm null sd. Depth-L1 over
this support is noise: no method could have won or lost on it.

Deficit-to-noise ratio (deficit = how much worse the vacated region already
renders than its own surroundings = the ceiling on what perfect ghost removal
could recover):

| candidate | deficit | null sd | ratio | verdict |
|---|---|---|---|---|
| `ghost_excess_psnr` (unbounded support) | 3.246 dB | 0.327 | **9.9×** | usable |
| `freshvac_excess_psnr` (30-frame window) | 1.807 dB | 0.275 | 6.6× | usable |
| `ghost_excess_depth` | 0.204 cm | 1.941 | 0.1× | **unusable** |
| `freshvac_excess_depth` | 0.259 cm | 1.377 | 0.2× | **unusable** |

Two fixes were built and measured; **only one worked, and it is not the one
that looked more principled**:

- The **complement contrast** does not rescue depth (0.1× → 0.2×). The
  non-vacated sliver is 16% of the support and is itself noisy.
- The **recency window** (`static_bg_vacated_window_frames`, default 30) halves
  the support (203284 → 100044 px, 66% → 33% of the image) and does shrink the
  noise (sd 0.327 → 0.275 dB), but it shrinks the *deficit* more (3.25 → 1.81
  dB), so the ratio gets **worse**. The windowed complement contains the older
  vacated area, which carries ghost of its own, so the reference is contaminated.
- What actually mattered was the **modality**: depth-L1 → PSNR, on the
  pre-registered support. Recorded so the window is not mistaken for the fix.

Mechanical root cause of the depth failure: `past_union` unions every earlier
dynamic mask with no decay, so after 439 frames of a roaming mover it covers
**84% of the static support / 66% of the image**. "Where the mover has ever
been" is the whole scene — which is why the metric tracked global map quality.

### 8.3 The deeper problem: the poses are noisier than anything we render from them

`ate_rmse_cm` on self-tracked balloon is **29.97 ± 2.62 cm** across the 7
replicates. Every rendering metric is computed from those poses, and the depth
errors we call "ghost" (21–27 cm) are *the same order as the pose error*. A map
metric cannot be cleaner than the trajectory it renders from.

Consequence: at 2 seeds, on this sequence, **no map metric separates prune from
the deferred family** — including the one this campaign and R2-P01-E2 both
reported as the durable result:

| metric | prune (n=2) | deferred family (n=7) | diff | \|d\|/null sd | verdict |
|---|---|---|---|---|---|
| `static_vacated_depth_l1_pen_cm` | 21.819 | 23.425 | −1.607 | 1.03 | buried (Welch t=−2.50, df≈1) |
| `static_depth_l1_pen_cm` | 21.270 | 22.928 | −1.658 | 0.94 | buried |
| `static_vacated_psnr` | 21.421 | 21.103 | +0.318 | 1.14 | buried |
| `static_ssim` | 0.812 | 0.808 | +0.004 | 1.12 | buried |
| `refined_num_gaussians` | 24280 | 26505 | −2225 | 0.40 | buried |
| `ghost_excess_psnr` (calibrated) | −3.998 | −3.246 | −0.752 | 2.30 | **sign flips**, but Welch t=−1.36 |
| `ate_rmse_cm` | 35.625 | 29.966 | +5.659 | 2.16 | resolvable — prune tracks *worse* |

**"Prune beats deferred on vacated-region ghost" is a 1.6 cm claim on a metric
with a 1.56 cm null sd.** It is not established. On the calibrated PSNR contrast
the ordering reverses, though not significantly, and that contrast has its own
confound: arm A's non-vacated PSNR (26.19 on seed 0) is the highest of all nine
runs, i.e. prune is better *everywhere* but more so in the 16% periphery, which
drags its contrast down. Neither direction is safe to claim from these data.

R2-P01-E2's version of the same claim was never noise-calibrated either and
uses the same pose-noise-dominated metric; it should be re-scored the same way
before being cited again.

### 8.4 What this implies for the design, not just the metric

The claim under test is **map admission**, and the positioning is explicitly
"tracker-orthogonal". Measuring it through a trajectory with 30 cm of error and
±2.6 cm of run-to-run jitter puts the dominant noise source inside the very
channel the claim does not concern.

`Oracle.gt_pose: true` already exists in this repo for exactly this isolation
("force GT camera pose + skip Adam tracking; mapping runs normally",
`slam_frontend.py:874`). Running the arm contrast under fixed GT poses (with
`Training.lr.cam_rot_delta/cam_trans_delta: 0.0` so the backend cannot drift
them off GT) would remove the pose channel entirely and is *aligned with* the
claim rather than a concession to it. It cannot be the paper's main table —
that must stay full SLAM — but it is the correct screening instrument, and it
is the difference between a 2-seed experiment that can answer and one that
cannot.

**Not yet measured:** how much of the noise actually collapses under fixed
poses. That needs one small run set and is the recommended pre-flight before
any 9-run re-run.
