## 3. 为什么 frac 这个测量误导（修正）

真正该问的是「密度控制是否改变**绝对**低 op 存量」，而不是比例。用绝对量看：
- LO（更激进插）确实把低 op 存量从 BASE 的 ~3-4.5k 抬到 ~6.5-7.8k（插得更多 → 更多残留），**但这是「地图变大带来的比例稀释」，不是「tail 变宽」。**
- HI（更少插）绝对低 op 存量 ~2-5.5k，**不比 BASE 多**，frac 高纯粹是分母小。

**结论：densify 阈值确实影响低 op 绝对存量（LO 更多），但 frac 把它伪装成「HI 反常」的假象。** 我的原预测方向（LO 更多）用绝对量看其实成立，是 frac 这个 ratio 把它污染了。

## 4. `<0.7→<0.01` 高占比（~78-80%）——真正的机制信号

所有终图里 `op<0.7` 的高斯，绝大部分（约 78%）都落在 `<0.01`。Prune 的死亡阈值是 0.7（`densify_and_prune` 里 `prune_mask = opacity < gaussian_th=0.7`），如果 prune 正常工作，终图存活高斯应当 opacity ≥0.7。但终图却有 25-45% 高斯 `<0.7`、其中近 8 成 `<0.01` ⇒
**存在一条「把高斯 opacity 压到 0.7 以下但不被 prune 清掉」的路径。** 最可疑 = `reset_opacity_nonvisible`（`slam_backend.py:510`，把非可见高斯 sigmoid 压回 0.4，每 ~2001 迭代一次）——它把一批高斯压到 0.4，之后优化可能继续往下推，最终落到 <0.01，且在下一次 prune 前已存活。**这与 densify 阈值无关**，是独立于 C 实验的另一条机制。

## 5. 待做零 GPU 判别（下次继续）

检查终图 opacity 分布是否有**峰在 0.4 附近**（reset 产物）或**单调堆积在 <0.01**（优化后持续下压）。用已存 10 个 PLY 画直方图即可定位。若峰在 0.4 ⇒ reset 是低 op 主因；若都堆 <0.01 ⇒ 是优化/竞争压下来的。

## 7. 追加：histogram 判别（opacity 分布峰位，CPU-only，同 10 PLY）

检查是否 reset_opacity_nonvisible(0.4) 峰或 init(0.5) 峰，或单调堆积 <0.01。

| seq | arm | N | %<0.01 | %[0.38,0.42] | %>=0.7 | %[0.5,0.55] |
|---|---|---|---|---|---|---|
| balloon | lo | 58518 | 11.23 | 1.04 | 61.46 | 1.74 |
| balloon | base | 27648 | 11.28 | 1.51 | 47.69 | 1.45 |
| balloon | **hi** | 25487 | 21.57 | 1.47 | **30.49** | 1.38 |
| balloon2 | lo | 69012 | 11.30 | 0.97 | 64.88 | 1.14 |
| balloon2 | base | 70746 | 6.45 | 0.74 | 75.01 | 1.25 |
| balloon2 | **hi** | 18380 | 10.72 | 1.58 | **50.79** | 1.68 |
| mv_no_box | lo | 82193 | 9.54 | 0.91 | 66.00 | 1.12 |
| mv_no_box | base | 38678 | 8.16 | 1.22 | 62.48 | 1.20 |
| mv_no_box | **hi** | 26091 | 15.44 | 1.49 | **36.27** | 1.69 |
| mv_no_box2 | lo | 133043 | 14.64 | 0.91 | 57.38 | 0.95 |

**判别结论：**
1. **reset(0.4) 不是低 op 主因**——`%[0.38,0.42]` 全部仅 ~0.7-1.6%，远不足以解释 10-25% 的 <0.01。
2. **init(0.5) 残影也不显著**——`%[0.5,0.55]` ~1-1.7%。
3. **真正信号 = HI 的 `%>=0.7` 整体下移**：HI 三序列 30/51/36%，明显低于同序列 LO(61/65/66%)与 BASE(48/75/62%)。**HI 的地图整体更"半透明"**——高不透明高斯占比下降、低 op 占比上升，opacity 分布整体左移而非某个峰。
4. **`%<0.01` 与 `%>=0.7` 近似互补**（HI 低不透明 → 高 %<0.01）。

**推论（机制假说，需 codex 复申 + 待验证）**：密度(每处覆盖高斯数)参与 opacity 竞争。
- 密度高(LO)：区域充分簇拥 → 代价函数推胜出者高不透明、败者被 <0.7 prune 清掉 → 终图高不透明占比高、tail 相对小。
- 密度低(HI)：覆盖稀疏 → 单个高斯"偷懒"留在低 opacity 不触发 prune(prune 只看 opacity<0.7 是否必要) → 大量半透明浮渣留存，`%<0.7` 高、`%>=0.7` 低。
- 这比 codex 的"纯分母效应"更进一步：HI 的 `%>=0.7` 绝对占比也真降，不只是分母小。

**对 C 实验的最终判断**：`frac_lt_001` 作为「密度控制 → tail 宽度」的 proxy 不强（被地图大小混淆），但 histogram 显示**密度确实影响 opacity 分布形态(高/低 op 占比结构)**——只是方向与"插多→tail 宽"相反（插少 HI → 低 op 占比高）。这是一个**值得继续探索的真机制信号**，指向"密度影响 opacity 竞争/分布"，而非我原预测的"出生率直接加宽 tail"。
