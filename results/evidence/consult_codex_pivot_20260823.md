# codex 对抗咨询 —— "项目被自身框架禁锢"诊断 + 方向发散（2026-08-23）

> thread `01a02eed-e404-7bd0-bdd4-d71cc06f7611`，分支 `ours-v3`。
> 背景：exp32→41 十轮全负/INDETERMINATE 后，用户诊断"项目的方法一直禁锢着方向，
> 不管怎么探索都不能发散"。本轮咨询请 codex 反打该诊断 + 评估三个跳出方向。

## Q1 禁锢诊断：CONFIRMED（置信度 0.93）

**禁锢根源排序**（不是单一因素）：
1. **首要：问题框架本身**——"动态像素 = 污染，必须从静态优化中排除/降权"。
   exp32-41 改的只是锚点/配额/EMA/作用域，全是同一个目标的局部修补。
2. 次要：MonoGS 的静态表示架构把项目推向这个框架（是放大器，不是牢笼本身）。
3. 更深层：判据围绕"静态 SLAM 是否被干扰"组织，而非"动态场景是否被解释完整"。

> 换任何静态 3DGS 基座，只要目标仍是排除动态，仍会回到同一搜索空间。

## Q2 方向选择：方向1 的目标 + 4D-lite 的形态（置信度 0.84）

**推荐主线 = Reliability-guided dynamic residual reconstruction**：
1. 保留现有静态 tracking/mapping backbone（4-14× 资产不动）；
2. ReliabilitySignal 从"loss 权重"翻转为"动态候选出生标签"；
3. 候选区域建**独立动态高斯集合**，只优化低维运动参数（motion scaffold）；
4. 静态 BA 与动态重建共享观测、不共享自由度；
5. 先证三件事：静态位姿不恶化 / 动态区域可重建 / 无分割网络也能工作。

四个标准评估：资产利用=强；3-4月可交付=中高（前提是 residual/对象级，不做完整 4DGS）；
新颖性=中高；跳出排除框架=是。

**方向2（换 VGGT 基座）判为"换更强前端，不是自己的方法"**——foundation prior 会
成为主贡献，ReliabilitySignal 退化成胶水；适合做 oracle/对照，不做主线。
**方向3（measurement paper）单独不够**——缺跨基座外部有效性 + 可迁移原则 +
至少一个正向方法；应作为方法论文的实验骨架。

## Q3 最大技术风险：错误归因正反馈（置信度 0.91）

> 最危险的不是显存/速度，是**错误动态归因形成不可逆的错误吸引盆**。

4D 分支新增三种竞争（动静高斯解释权 / 标签-运动估计互相强化 / 对象身份漂移），
可能比 44→97cm 双稳态更严重的多峰。**第一周就要做的吸引盆探测**（先于任何完整实现）：
1. 固定场景固定 seed 的多初始化矩阵（出生阈值/时刻/初速/动静比例）→ 报
   median/IQR/失败率/worst-quartile；
2. 分阶段冻结实验（分别冻位姿/静高斯/动高斯/scaffold）定位失败来源；
3. **可逆出生测试**：关掉动态标签能否恢复静态解释（不能 ⇒ 不可逆污染）；
4. 合成可控场景（纯静/纯平移/周期运动/动静交界/短时遮挡重现）；
5. 双稳态口径提前注册（每 config ≥5-10 seed，主指标=失败率+worst-quartile）；
6. 硬 kill criteria（静态 ATE 失败率上升/动态地图方差超阈/冻结动态分支即恢复）。

**明确不做**：先做复杂生命周期/eviction/alpha-carve——那些是后处理，
不能解决错误吸引盆（与本项目死清单独立地一致）。

## Q4 最坏情况：能拼稿但不够 CCF-C 主会（置信度 0.88）

现有资产（强 baseline + 机制结论 + 失败模式 + 评估纪律）缺三样：
1. **外部有效性**（跨基座/跨数据集，否则被读成 MonoGS 特例）；
2. **可迁移原则**（如"方差-偏置状态 ⇒ 何时抑制/何时重建"的决策法则）；
3. **至少一个正向新方法**。

纯"我们试了很多 mask 方法大部分失败"基本不够。最坏情况可投形态 =
机制诊断 + 可靠性基准 + 小型正向方法 + "何时排除/何时重建动态"边界，
投 workshop/benchmark/systems 或 CCF-C 边缘。
