## 1. 预注册判据（跑之前定死，见 REVIEW §7.5 / NEXT_SESSION_PROMPT §3.1）

> 在窗口 **f360–f385** 内，`anchor_frac_s90` 或 `anchor_ratio_s90` 的变化幅度 ≥ **15%**，
> **且**该序列前 350 帧的任意等长滑窗内不出现同等幅度的变化。
> 3 个 seed 至少 2 个满足，且至少 1 个 seed 确实发生 ATE 崩溃。

**"变化幅度"的操作化**（判据落地时定义，读锚点列之前）：窗口起末**电平位移**

```
amp(W) = | med(x[窗口末 1/3]) − med(x[窗口首 1/3]) | / | med(x[窗口首 1/3]) |
```

取中位数而非均值，单帧崩不出拐点。之所以是"起末电平位移"而不是别的：参照量本身就是这个形状——
`flow_valid_frac` 在 f368–380 从 0.54 掉到 0.43，即 −20%。窗内**峰谷幅度**也一并打印，
但**明确标记为 SECONDARY、不参与判决**：看到位移判不出来再改用峰谷，正是本项目预注册要防的 HARKing。

**崩溃阈值**：全轨迹 `ate_rmse_cm ≥ 10`。f3_st_hf 双稳态两支在 ~2–3 cm 与 ~30–36 cm
（exp25 / exp26 / P9），10 cm 两侧各留一个数量级。

## 5. 三条超出"判负"本身的读数

**① 幅度差一个数量级，不是差一点。** 判据要 ≥15%，锚点量给的是 0.5%–9.3%。
即便把阈值放宽到 10%，仍然全灭；放宽到 5% 才有三条勉强够到 —— 那时 null_max（34%–66%）
早就把它们全部淹没。**这不是阈值定高了的问题。**

**② 第二个 conjunct（前 350 帧无同幅变化）败得更彻底。** 前 350 帧的等长滑窗里，
`anchor_frac_s90` 的最大位移是 **0.35–0.54**、`anchor_ratio_s90` 是 **0.46–0.66** ——
比崩溃窗口内的位移大 **5–100 倍**。这条序列的锚点量**到处都是拐点**，
预注册判据要排除的正是这种情况。

**③ 方向还反了，而且崩与不崩看不出区别。** 三个 seed 的 `anchor_frac_s90` 在崩溃窗口内
一律**上升**（0.66→0.70 / 0.67→0.70 / 0.67→0.73）—— 追踪要崩的时候，被信任的锚点**变多**了。
而且**没崩的 seed2 的幅度（0.093）比两个崩了的 seed（0.068 / 0.051）都大**。
一个连"崩没崩"都分不开、方向还与假设相反的量，做不了触发器。

## 6. 对参照量本身的诚实说明

`flow_valid_frac` 在窗口内复现了 P9 记的 −15%（0.52 → 0.44），**但它自己也过不了第二个
conjunct**：前 350 帧 null_max = 0.309 > 0.15。所以严格按这条可证伪判据，
`flow_valid_frac` 同样**不是**崩溃的特异预测量 —— 它只是"在崩溃时也在掉"。
这不改变 M2 的判负（锚点量连它的幅度都没达到），但它提示：
**"崩溃前某个量在变差"这个叙事家族，在 f3_st_hf 上可能整体不成立**，
因为这条序列的所有支撑量都在全程剧烈波动。

---

## 7. 决策

- **Design B（锚点存活率触发关键帧）判负。M3 的 48 run 不申请、不执行。**
- 探针代码保留（default-off，`anchor_probe: false`），因为它对"支撑集在崩溃期如何演化"
  这个问题给出了可复用的只读测量；但**不再作为方法候选**。
- 不重跑更多 seed：0/3 通过、崩溃已落在窗口内、幅度差一个数量级、
  且 null 幅度是信号的 5–100 倍 —— 加 seed 不可能翻转这四条中的任何一条。
